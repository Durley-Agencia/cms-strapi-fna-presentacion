01 · Objeto y alcance

Un manual de operación, no de intención

Este documento describe cómo funciona el CMS tal como opera hoy: capacidades, límites y responsabilidades por perfil. No reemplaza la capacitación funcional interna ni las decisiones de gobierno de contenido.

Qué cubre

Acceso y navegación del panel · gestión de contenido en Single y Collection Types · componentes, relaciones, campos multimedia y SEO · operación bilingüe (ES/EN) · Biblioteca multimedia · flujo editorial propio · auditoría y trazabilidad · administración avanzada para perfiles autorizados.

Qué queda fuera

Desarrollo técnico de frontend o backend · modificación directa de base de datos · despliegue de infraestructura · definición técnica de nuevos modelos de datos · herramientas internas de indexación o búsqueda fuera del uso normal del editor. Estos temas viven en "Documentación código" y "Documento arquitectura".

03 · Marco general del CMS

Qué rol cumple Strapi, y qué puede salir mal

Strapi es el repositorio editorial estructurado y el punto único de administración de contenido del ecosistema FNA. El frontend en Next.js lo consume mediante regeneración incremental (ISR) y archivos de fallback: una arquitectura que exige disciplina editorial.

Riesgo 1, Contenido incompleto

Publicar sin completar campos obligatorios deja información rota o mal presentada. Prevención: checklist por rol antes de enviar/aprobar. Corrección: completar campos y republicar.

Riesgo 2, Cambios no inmediatos

La ISR y la caché de CDN (Cloudflare) hacen que un cambio publicado no sea visible al instante. Prevención: planificar con anticipación. Corrección: escalamiento técnico si persiste.

Riesgo 3, Fallback desactualizado

Si Strapi no responde, el frontend usa JSON de respaldo: tasas vencidas, horarios cerrados que aparecen abiertos. Prevención: revisar el fallback regularmente y purgar caché tras actualizar.

Principio institucional de completitud: un campo faltante nunca es neutral. Puede afectar la visualización, la consistencia entre idiomas, los metadatos o la publicación efectiva del contenido.

05 · Estructura del panel

Un panel adaptado a la identidad institucional del FNA

Acceso vía https://fnawebdev-admin.agencianacionaldigital.com.co/, personal e intransferible. Cada usuario administra su nombre visible, correo, contraseña e idioma de interfaz sin afectar permisos ni estructura del CMS.

Módulos principales

Gestor de Contenido: páginas, entradas y registros.

Biblioteca multimedia: carga y organización de archivos.

Auditor del Sitio: performance, accesibilidad, SEO, enlaces rotos.

Auditoría / Trazabilidad: registro exportable de operaciones.

Configuración: usuarios, roles, tokens API y webhooks.

Personalización visible

"Content Manager" se presenta como Gestor de Contenido, y el plugin propio export-import-fna aparece como Exportar/Importar.

Se ocultan de la experiencia estándar: Review Workflows nativo, Single Sign-On, Content History, Releases, Marketplace y Cloud, sin que esto implique que estén desinstalados del sistema base.

    07 · Gestión de contenido

    Cómo está construido el contenido por dentro

    Collection & Single Types

    Collection Types para entradas repetibles (noticias, FAQ). Single Types para páginas únicas (Inicio, Contacto). Vista de lista para navegar entradas, vista de edición para el formulario completo.

    Guardado y publicación

    Guardar deja el contenido en Borrador, no visible al público. Publicar lo hace visible. Despublicar revierte a un estado no visible sin eliminar el contenido del CMS.

    Campos y validaciones

    Los campos obligatorios llevan asterisco rojo. Cada tipo de contenido define sus propias reglas de validación (longitud, formato, requerido).

    Componentes repetibles

    Permiten agregar múltiples elementos del mismo tipo dentro de un contenido (por ejemplo, una lista de preguntas frecuentes dentro de una página).

    Relaciones y UID/slugs

    Las relaciones vinculan contenidos entre sí. El UID/slug es el identificador único usado en las URL y rutas de navegación del portal.

    Zonas dinámicas

    La zona "Secciones" arma páginas combinando bloques del catálogo. Los "Contenedores/Secciones reutilizables" son bloques compartidos entre páginas; un cambio se propaga a todos sus usos.

    Páginas dinámicas y micrositios (7.10.1 a 7.10.3): el content-type «Páginas» funciona como constructor de páginas; los micrositios organizan una jerarquía de página padre, páginas hijas y ruta de navegación.

    Plantillas de página (7.10.6): el campo "Es plantilla" permite crear una página base para duplicar y reutilizar como punto de partida de páginas nuevas.

    Banner unificado (7.10.7): bloque estandarizado para las cabeceras visuales de página.

    Listas (7.10.8): el plugin "Listas" y el bloque "Lista (vinculada)" permiten conectar catálogos de contenido a una página sin duplicar información.

    Carpeta de documentos (7.10.9): bloque para agrupar descargas relacionadas (PDF, Excel) dentro de una página.

    09 · Guía de troubleshooting

    Los siete problemas más comunes, resueltos

    Si el estado dice "Borrador": no está publicado, hay que completar los campos obligatorios y publicar. Si dice "En Revisión": espera aprobación. Si dice "Publicado" y aun así no aparece tras 2 minutos: limpia caché del navegador (Ctrl+Shift+Del) y recarga. Verifica también que el locale correcto (es/en) esté publicado. Si persiste tras 5 minutos, es un problema técnico: contacta a soporte@fna.gov.co.

    Otro usuario está editando el mismo contenido (plugin content-lock). Espera hasta 30 minutos (se libera automáticamente), contacta a esa persona, o pide al administrador que fuerce el desbloqueo. No sirve de nada cerrar el navegador para intentar desbloquearlo antes de tiempo.

    Lee el mensaje exacto: "obligatorio" (rellena el campo), "email inválido" (revisa el formato), "máximo X caracteres" (acorta el texto). Corrige el campo señalado en rojo y guarda de nuevo.

    La sesión se cierra tras 5 minutos de inactividad. Guarda cada 5 minutos como hábito. No hay recuperación automática de un borrador no guardado tras cerrar sesión.

    Usa la búsqueda en lugar de navegar por carpetas; si sigue lenta, acota a una carpeta específica; considera cargar una imagen nueva en vez de buscar una antigua; pide al administrador que limpie archivos huérfanos.

    Abre el contenido, lee con atención el comentario de rechazo en el panel "Flujo Editorial", haz los cambios solicitados y envía nuevamente a revisión.

    Tu rol no tiene permiso para ese tipo de contenido. Pide a tu supervisor el rol correcto, asigna la tarea a alguien con permiso, o contacta al Administrador FNA para expandir tus permisos.

    11 · Gestión de idiomas

    Español primero, inglés después, sin excepciones

    i18n habilitado con locale por defecto es y locale adicional en. Cada idioma es una versión independiente: publicar en español no publica automáticamente en inglés.

    Reglas institucionales

    1. Completar primero la versión en español.
    2. Trasladar al inglés solo contenido validado y vigente.
    3. Revisar títulos, descripciones, SEO y medios por idioma.
    4. No dejar locales a mitad de diligenciamiento si hacen parte del alcance publicado.

    Riesgos por desalineación

    Información parcial para el usuario internacional, descripciones meta incongruentes, experiencias distintas entre idiomas, o activación de fallback por locale ausente.

    1. Localizar el selector de locale en la parte superior derecha del formulario (por defecto Spanish/es).
    2. Cambiar al locale English (en) desde el desplegable.
    3. Traducir cada campo localizable: títulos, subtítulos, descripciones, texto enriquecido, botones.
    4. Completar todos los campos y guardar como borrador en el locale inglés.
    5. Enviar a Flujo Editorial (Borrador → En Revisión) para que el Editor valide la traducción.
    12 · Gestión de archivos e imágenes

    Un único punto oficial para todo activo digital

    Los archivos deben cargarse mediante campos de media; deben evitarse URLs manuales cuando ya existe un campo de carga. Los archivos se almacenan en Azure Blob Storage.

    Organización de carpetas

    Por dominio funcional o sección del portal: personas/, transparencia/, prensa/, home/, compartidos/. Facilita la operación, pero no sustituye el control de permisos.

    Reutilización vs. carga nueva

    Reutiliza cuando el archivo es válido para varios contenidos o es institucional/compartido. Carga uno nuevo cuando el contenido requiere una versión específica o el archivo vigente debe conservarse para otras páginas.

    Metadatos y calidad

    Nombre comprensible, texto alternativo (obligatorio para accesibilidad), pertinencia de la imagen y vigencia del documento asociado.

    13 · SEO editorial

    El SEO es parte del contenido, no un anexo opcional

    Campos del componente SEO

    metaTitle · metaDescription · metaImage · openGraph · keywords · metaRobots · metaViewport · canonicalURL · structuredData

    Restricciones reales

    metaTitle: requerido, máx. 60 caracteres. metaDescription: requerida, entre 50 y 160 caracteres. metaImage: opcional. structuredData: campo JSON heredado. No deben crearse nuevos campos JSON para necesidades editoriales.

    Ejemplo bien diligenciado: crédito hipotecario (Personas, sección Vivienda)

    metaTitle (53 car.): "Crédito hipotecario FNA: tasas, plazos y requisitos". No repite el H1 literal, agrega palabras clave y la marca institucional.

    metaDescription (148 car.): "Conoce los requisitos, tasas vigentes y plazos del crédito hipotecario del Fondo Nacional del Ahorro. Solicita tu vivienda propia con respaldo institucional." Resume el contenido real, sin repetir el metaTitle.

    15 · Auditoría y trazabilidad

    Todo queda registrado, y el sitio se audita solo

    Plugin de auditoría (audit-trail)

    Registra creación, modificación, eliminación, publicación, despublicación, carga de archivos, autenticación y eventos administrativos, con metadatos de la petición (ruta, usuario, IP, duración). Exportable en CSV y JSON. Retención por defecto de 90 días, hasta 500.000 registros. Acceso: Administrador FNA y Super Admin por defecto.

    Controles de sesión

    Token de acceso: 6 horas. Token de refresco: hasta 30 días. Sesión inactiva se cierra a los 30 minutos, con aviso 5 minutos antes. Bloqueo pesimista de edición (content-lock) evita ediciones simultáneas.

    Auditor del Sitio: auditoría automática del portal

    Ejecuta análisis bajo demanda sobre una URL específica y conserva historial comparable entre ejecuciones:

    Performance

    Core Web Vitals vía Google PageSpeed Insights (LCP, CLS, INP, TBT, FCP, TTI).

    Accesibilidad

    Cumplimiento WCAG 2.1 con mapeo de violaciones por nivel A/AA/AAA.

    SEO

    Metadata, indexación, Open Graph/Twitter Cards, jerarquía de encabezados.

    Enlaces rotos

    Detección automática con listado de URL y código de error HTTP.

    Genera puntajes de 0 a 100 por categoría, gráfico de tendencias en el tiempo y comparación entre ejecuciones. Sirve como evidencia verificable ante auditorías internas o externas, pero no sustituye la validación humana de accesibilidad (lectores de pantalla, navegación por teclado).

    16 · Administración avanzada

    Funciones restringidas a perfiles autorizados

    Usuarios y roles

    Creación de cuentas, actualización de datos, reasignación de roles y desactivación de acceso. La modificación de la matriz de permisos debe ser excepcional y evaluada por impacto.

    Tokens API y webhooks

    Función técnica, no editorial ordinaria. Su modificación puede afectar integraciones y la revalidación del frontend.

    Content-Type Builder

    Herramienta técnica para tipos de contenido, componentes, campos, relaciones y validaciones. No es un instrumento de edición ordinaria. Requiere análisis funcional y técnico previo.

    Instancia actual: Strapi 5 (v5.32.0), Node.js 18 a 22. Plugins propios: state-workflows, audit-trail, content-lock, content-history, meilisearch-sync, site-auditor, google-analytics-dashboard. Plugins de terceros: @strapi-community/plugin-seo, @fourlights/strapi-plugin-deep-populate, strapi-provider-upload-azure-storage, export-import-fna, entre otros.

    Antes de actualizar: revisar changelog y guías de migración oficiales, verificar compatibilidad de Node.js y de plugins propios/terceros, respaldar base de datos PostgreSQL (con restauración de prueba) y los activos en Azure Blob Storage, planificar ventana de baja actividad y preparar un entorno de staging.

    Actualización del core: rama dedicada en el repositorio, actualizar @strapi/strapi + plugin-users-permissions + plugin-cloud en la misma versión, npm install, reconstruir plugins y panel administrativo, validar funcionalidades críticas (autenticación, edición, publicación, Flujo Editorial), desplegar primero en staging y luego en producción.

    Plugins de terceros: actualizar uno a la vez, revisar notas de versión y configuración en config/plugins.ts, reconstruir y probar la funcionalidad específica de cada plugin.

    Post-actualización: verificar acceso con cada rol operativo, validar un ciclo completo del flujo editorial, revisar el módulo de Auditoría, confirmar la conectividad con Azure y con el frontend Next.js, monitorear logs, y tener listo un procedimiento de rollback ante incidencias críticas.

    17 · Reglas de calidad y consistencia

    Once reglas de cumplimiento obligatorio

    • 01 No dejar contenido crítico incompleto.
    • 02 Completar siempre los locales requeridos por el alcance del contenido.
    • 03 Reutilizar componentes, estructuras y patrones existentes.
    • 04 No crear nuevos campos JSON para necesidades editoriales.
    • 05 Escalar al equipo técnico lo que no pueda modelarse de forma amigable.
    • 06 Usar campos de media para imágenes y documentos disponibles.
    • 07 Evitar URLs manuales cuando el modelo ya contempla carga de medios.
    • 08 Mantener coherencia entre contenido visible, SEO, medios y relaciones.
    • 09 Verificar el impacto de publicación en ambos idiomas cuando aplique.
    • 10 Revisar el contenido desde el punto de vista funcional, no solo del formulario.
    • 11 Recordar que contenido incompleto puede causar fallback o experiencia inconsistente.
    18 · Publicación y visibilidad en el portal

    Publicar en Strapi no es lo mismo que ser visible ya

    Regeneración incremental (ISR)

    El frontend Next.js regenera páginas cada hora en múltiples secciones. El contenido publicado puede tardar en reflejarse; la primera visita tras el vencimiento puede seguir sirviendo la versión previa.

    Fallback de contenido

    Si Strapi no responde o los datos están vacíos, el frontend usa JSON de respaldo: puede mostrar información antigua, protegiendo la continuidad del servicio a costa de exigir mayor rigor editorial.

    Cambios urgentes

    Publicar no basta por sí solo cuando se requiere visibilidad inmediata. La revalidación manual es un procedimiento técnico que debe coordinarse con el equipo responsable del frontend.
